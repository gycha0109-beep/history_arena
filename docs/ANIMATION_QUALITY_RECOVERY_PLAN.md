# 레전더리 배틀 — 캐릭터 그래픽 품질 회복 작업 지시서

**확정일:** 2026-11-12  
**상태:** 기존 검증 영상 시각 품질 **불합격** / 새 제작 파이프라인 채택  
**범위:** 무사시(오른손 장검·왼손 단검), 이소룡, 첫 5초 검술·피격 장면  
**스택 변경 없음:** Godot 4.7.2 + Blender 5.2 LTS 계열 + 검증된 기본 모션 + 3D 기반 2.5D. 정확한 소프트웨어 패치 버전은 작업 PC에서 확인.

## 0. 최우선 결정

**기존 CesiumMan 임시 모델에 코드를 덧붙여 검술처럼 만드는 방식 중단.**

기존 테스트는 'GLB 가져오기 / 손뼈 소켓 추종 / 무기 배율 유지 / 720×1280 영상 출력'에 한해서만 성공이다. **걷기, 무기 그립, 이도류 자세, 공격/회피/피격, 캐릭터 외형은 전부 시각 품질 불합격**이다. 자동 검사 성공만으로 다시 영상 품질 통과로 보고하지 않는다.

기존 `scenes/qa_rigged_sample.tscn`, `scripts/qa/rigged_sample_preview.gd`, `tools/build_dual_qa_swords.py`는 **비주얼 제작 기준이 아닌 골격·무기 연결 회귀 검사 전용**으로 유지한다. QA 영상과 최종 품질 검증 영상은 파일명/폴더/설명에서 반드시 분리한다.

## 1. 기존 결과의 실패 원인과 폐기할 접근

| 영상에서 관찰된 실패 | 실제 제작상 원인 | 중단할 방식 |
|---|---|---|
| 캐릭터가 걷지 않고 미끄러지거나 정지 | 보행 애니메이션을 꺼서 발이 움직이지 않게 함. 게임 이동과 보행 사이 연결 없음 | 발/다리 뼈를 고정해서 '접지 성공' 처리 |
| 칼날이 몸통·반대팔을 관통 | 손목과 검만 회전. 어깨·팔꿈치·몸통·상체 회전·검 궤적을 함께 설계하지 않음 | 실시간 GDScript 손목/검 회전으로 검술 제작 |
| 칼을 쥐는 손이 부자연스러움 | 샘플 리그에 손가락 뼈가 없어 무기 주변에 가짜 손 메시를 추가 | 검 모델에 임시 손바닥/손가락 메시를 붙이는 방식 |
| 좌우 검이 독립적으로 겉도는 이도류 | 기본 공격 모션은 검 2자루의 실제 손·팔·체중 이동을 고려하지 않음 | 일반 걷기/기본 펀치 모션에 검만 붙이고 '이도류'라고 판정 |
| 부자연스럽게 정지한 머리·상체 | 머리 움직임을 0으로 고정하고 몸통 이동을 인위적으로 억제 | 눈에 띄는 흔들림을 무조건 0으로 만드는 처리 |
| 테스트는 통과하지만 그림은 엉성 | 검사 대상이 수치/소켓 중심, 시각 평가와 다른 성공 조건 | 자동 검사 성공 = 완성된 게임 화면으로 보고 |

## 2. 확정 제작 파이프라인

1. **제작용 캐릭터 확보:** 무사시의 고품질 전신 3D 모델. 정면·측면·후면에서 비율이 유지되고, 손가락이 독립 분리되어 실제 그립이 가능한 손이어야 함. 우선 Meshy 모델을 **실물 결과로 검증**, 기준 미달이면 적법한 라이선스의 기존 인체 모델 또는 Blender 리토폴로지/조형으로 전환.
2. **골격/손가락 리깅:** 어깨·팔꿈치·손목·엄지/검지/나머지 손가락·골반·발목·발가락 등 동작에 필요한 뼈 확인. Meshy API 사용 시 `include_fingers=true`를 **명시해야 함**(기본값 false). 손가락 자동 리깅에 실패한 모델은 그립 품질 대상에서 제외.
3. **Blender에서 모션 완성:** 기본 걷기는 재활용 가능하나 '걷기→정지→이도류 기본자세→장검 베기/단검 가드→회복'은 실제 리그에 맞춰 키프레임과 IK로 제작. 손 목표 및 팔꿈치 방향을 함께 조절하고, 검날 경로가 자기 몸을 통과하지 않도록 전 구간 검사.
4. **고정된 그립 기준:** 검 모델의 손잡이 기준점/축을 통일. 오른손 장검, 왼손 단검을 각 손바닥의 실제 쥐는 위치에 배치. 검 자체는 독립 리지드 메시(스킨/모프/스케일 애니메이션 없음). 손가락은 손잡이에 접촉하도록 굽힌 포즈를 리그에 적용. 검을 움직여 팔을 우회시키지 않고 팔·몸통이 검술을 만들어야 함.
5. **모션과 이동 일치:** Blender의 제자리 보행(in-place) + Godot의 실제 X 이동 또는 한 번의 검증된 root motion 방식을 선택. 두 방식을 중복 적용하지 않음. 스탠스 발은 미끄러지지 않게 접지, 이동 발은 실제로 들었다 내려야 함. 근거 없는 다리 고정 금지.
6. **모션을 GLB로 내보내 Godot에 임포트:** `idle_dual`, `walk_forward`, `walk_backward`, `dual_cross`, `wakizashi_cut`, `hit_react`, `recover` 등 실제 클립 구분. BoneMap / Bone Rest / 방향 및 스케일 확인. Godot은 실제 완성된 동작의 전환·블렌딩·논리적 위치·판정을 담당하며 손목 검술을 매 프레임 생성하지 않음.
7. **이소룡 모델 및 실제 피격·회피:** 무사시 모션이 통과한 다음 별도 모델에 상대 공격에 반응하는 실제 피격/회피 모션을 준비하고 타격 순간과 동기화.
8. **최종 9:16 영상 출력 및 전 프레임 시각 검수:** Godot Movie Maker → FFmpeg. 모델 품질, 손잡이 접촉, 검날 자기 몸 관통, 발 접지, 얼굴 흔들림, 공격→피격 반응을 육안 확인.

### 도구 역할

- **Meshy:** 모델/기본 리그 후보를 확보하는 도구. 자동 생성물이 바로 최종 품질이라는 보장은 없음.
- **Mixamo:** 검술이 아닌 기본 보행/이동 등 후보. 리타기팅과 손/발 수정은 Blender에서 마무리.
- **Blender:** **검술, 그립, 발 접지, 무기 궤적의 최종 책임 도구**.
- **Godot:** 완성된 캐릭터 동작의 재생·연결, AI 결정, 판정·카메라·영상.
- **Python/FFmpeg:** 검사, 후처리, 자동 배치.

## 3. 실행 순서와 단계별 통과 기준

### 단계 A — 임시 QA와 제품용 영상 분리 (선행)
- 기존 CesiumMan 영상은 `QA/회귀 검사`로 표시. 최종 전투 영상·품질 증빙 목록에서 제외.
- 신뢰할 수 있는 원본 모델 파일, 모션, 각 파일의 사용 권리/출처를 한데 기록.
- **통과:** QA 영상이 실제 무사시 검술 완성으로 소개되지 않음.

### 단계 B — 무사시 모델과 손가락 리그 1개 확보
- 한쪽 얼굴만 좋아 보이는 프리뷰가 아닌 실제 GLB/FBX를 여러 각도에서 검사.
- 손바닥, 분리된 손가락, 뼈대, 의상 변형, 폴리곤 수, 리그 움직임 확인.
- **통과:** 양손 모두 엄지와 다른 손가락을 움직여 실제 손잡이를 감쌀 수 있음. 리그/형상이 불가능하면 채택하지 않음.

### 단계 C — 걷기/접근만 먼저 2초 시험
- 2초 동안 화면 내 실제 수평 이동(목표 약 1m 내외)과 최소 두 번의 분명한 발 접지/보행 동작.
- 시작/정지 시 갑작스러운 발 끌림·무릎 펴짐·몸통 순간이동 없음.
- **통과:** 화면상 명확히 걷고 있음. 지지 발이 딛는 동안 눈에 띄는 미끄러짐 없음(시험 목표 지지 발 오차 3cm 이내). 머리/상체는 살아 있지만 과장된 흔들림 없음.
- **실패:** 불합격 동작을 다리 고정으로 덮지 말고 Blender 보행/루트 이동부터 수정.

### 단계 D — 두 검 실제 그립+정지 가드 1초 시험
- 오른손 장검, 왼손 단검, 두 팔은 실제 검술 자세. 손목만 꺾지 않고 어깨·팔꿈치와 연동.
- 그립 오프셋을 움직이는 무기마다 따로 보정하되 뼈 배율은 검에 전달하지 않음.
- **통과:** 손가락이 손잡이를 감싼 상태가 앞/옆 각도에서 명확하고, 검 두 자루 모두 자신의 몸통·얼굴·반대팔을 관통하지 않음. 손잡이와 손바닥 사이 큰 틈이 없음(시각 QA 목표 1cm 이내).
- **실패:** 검만 돌리지 말고 캐릭터 리그에 그립 자세를 다시 제작.

### 단계 E — 실제 이도류 1회 베기 시험
- 장검의 주 공격과 단검의 견제/방어가 동시에 성립하도록 Blender에서 시작→가속→검 궤적→멈춤→회복 제작.
- 자기 몸통 관통·검 손잡이 손 이탈·검의 물리적 길이 변화가 없도록 주요 프레임과 중간 프레임 전체 확인.
- **통과:** 손·팔·몸통 회전과 검 궤적이 일관되고, 모션의 체중 이동/발 버팀이 납득 가능. 검격 속도와 공격 판정 시간이 일치.

### 단계 F — 5초 2인 전투 검증
- 0.0~1.4초: 대치→무사시 **실제 걸어서 접근**
- 1.4~2.0초: 이도류 가드/호흡/장검 선딜
- 2.0~3.1초: 장검 베기 + 단검 견제
- 3.1~3.9초: 이소룡 실제 회피 또는 피격 모션
- 3.9~5.0초: 양측 자세 회복
- **통과:** 걷기, 양손 그립, 자기 몸 관통 없음, 일관된 검 길이, 납득 가능한 상대 반응, 9:16 MP4, 동일 내용을 HTML로 재생 가능.
- 이 장면은 **그래픽 품질 검증용 연출**이며 실제 AI 대전 기록/승패 영상과 구분.

### 단계 G — 전투 AI와 연결
- 시각 검증 통과 이후에만 기존 AI의 `quick_cut`, `heavy_cut`, `wakizashi_cut`, `dual_cross`와 실제 모션 클립의 시작/유효/회복 구간을 연결.
- 판정·승패는 AI가 결정하고 애니메이션은 결과를 표현. 피격 타이밍은 동작과 일치.
- **통과:** 멈춤/중단/연속 공격/대전 재생에서도 무기와 몸 비율이 무너지지 않음.

## 4. 회귀 방지 체크리스트

- [ ] 실제 접근 **걸음**이 있는가? 위치만 바뀌거나 다리만 들리지 않는가?
- [ ] 왼손/오른손에 각각 실제 다른 검이 있는가?
- [ ] 손잡이를 실제 손가락으로 쥐고 있는가? 가짜 검 부착 손 형상은 제거됐는가?
- [ ] 장검과 단검이 자기 몸통/팔/얼굴을 통과하지 않는가?
- [ ] 검 길이·무기 배율과 캐릭터 신체 비율이 프레임 전체에서 일정한가?
- [ ] 발이 지면에 닿을 때 미끄러지지 않는가?
- [ ] 머리·목이 과하게 출렁이거나 완전히 부자연스럽게 고정되지 않았는가?
- [ ] 손/팔/몸통/발이 하나의 움직임으로 보이는가?
- [ ] 이소룡이 공격 타이밍에 실제로 반응하는가?
- [ ] Godot 실제 실행 → 5초 MP4 → HTML 재생 → 육안 검증까지 했는가?

**실패 항목이 하나라도 핵심 동작에 있으면 비주얼 완성으로 보고하지 않음.** 사각지대나 화면 잘라내기로 실패를 감추지 않는다.

## 5. 현재 구현 자산의 처리

**계속 사용:** Godot 기본 프로젝트, AI 전투/경기 기록, JSON 재생, Python 에셋 감사 도구, 독립 검 소켓, Movie Maker 출력, GitHub 검사, Windows 실행 파일.

**QA 전용 보존:** CesiumMan, Blender로 만든 QA 장검·단검, 손가락처럼 보이는 QA 검 메시, `qa_rigged_sample.tscn`.

**제품 화면에서는 사용 금지:** 테스트용 구형 모델 + 스크립트의 실시간 손목 강제 회전 + 양발 강제 고정 + 손가락처럼 보이는 검 메시.
