# 실제 AI 경기 자동 생성·하이라이트 선정·기록 재생

> 이 기능은 **실제 자동 전투를 여러 번 수행하고 그 결과 중 볼 만한 경기를 선택**합니다. 시뮬레이션 중 결과를 조작하거나 특정 인물에게 승리를 부여하지 않습니다.

## 사용 (Windows)

먼저 GitHub 최신본을 로컬에 안전하게 동기화한 뒤:

```powershell
# 서로 다른 시드로 실제 자동 대전 12경기 생성
.\run-dev.cmd -Mode batch

# 20경기를 시드 3400부터 생성
.\run-dev.cmd -Mode batch -Count 20 -FirstSeed 3400

# 가장 높은 점수를 받은 실제 경기 재생
.\run-dev.cmd -Mode replay

# 특정 경기 파일 재생 (직접 지정)
.\run-dev.cmd -Mode replay -ReplayFile 'res://captures/matches/match_3408.json'
```

**모델이 없는 상태에서도** 기록 생성과 선별은 정상 작동합니다. 재생 장면에서는 캐릭터 모델 누락 경고가 표시되고 체력·경기 시간·공격 사건을 읽을 수 있습니다. 실제 영상 품질을 보장하지는 않습니다.

## 저장 결과

```text
captures/matches/
  index.json             # 후보 경기 점수·순위·추천 경기
  match_3400.json         # 한 경기의 모든 60Hz 전투 상태·이벤트
  match_3401.json
  ...
```

선별 목록은 추천 점수가 높은 순서로 정렬됩니다. 최종 영상에 사용할 경기는 제작자가 직접 선택할 수도 있습니다.

## 어떤 경기를 추천하나?

현재 초안의 기준은 다음과 같습니다.

- 실제 타격 횟수, 두 인물이 모두 타격에 성공한 경기
- 서로 다른 기술이 등장한 경기
- 체력이 앞선 인물이 여러 번 바뀐 경기
- 종료 시점의 체력 차가 작은 경기
- KO가 있었는지, 경기가 지나치게 길지 않은지

이 점수는 **경기가 끝난 후에만 계산**되며 시드·승자·공격·피격·피해량을 변경하지 않습니다. 특정 캐릭터의 승리를 우선하지도 않습니다. 아직 영상 편집자의 주관적 재미 판단을 대체하지 못하는 **실험용 기준**입니다.

## 기록과 재생

- 기록 파일마다 시작 시드, Godot 버전, 전투 규칙 버전, 60Hz 전투 상태, 타격 이벤트, 승자 저장
- 재생 전 파일 형식·프레임 수·시간 순서·캐릭터 필수 값과 승패 정보를 검증
- **재생 화면은 AI를 다시 돌리지 않습니다.** 저장된 체력/위치/상태만 사용하므로 기존 시뮬레이션의 판정 결과가 바뀌지 않습니다.
- 스페이스: 일시 정지 / 좌우 화살표: 1초 이동 / Home: 처음
- `run-dev.cmd -Mode test`에서 실제 생성 → 저장 → 다시 읽기 → 같은 시드 재생 비교 검증

### 아직 별도 구현해야 하는 것

- 모델과 모션의 물리적 완성도 및 재생 위치 점프 시 애니메이션 시간 재동기화
- 카메라 선택, 슬로모션/강조 효과, 사운드, 재미있는 장면만 추출하는 영상 편집
- 경기 기록을 외부 버전에서도 재생하도록 이전 버전 변환 규약
- 1080×1920·60fps의 최종 영상 출력

### 재생 데이터 크기

60Hz 프레임을 전체 저장하는 방법이므로 경기 수와 길이가 늘면 JSON 용량도 증가합니다. 일단 한 번에 40경기까지 제한하며, 실제 용량을 측정한 뒤 압축 및 프레임 간 변화만 저장하는 방식으로 개선합니다. 생성된 JSON은 `.gitignore`의 `captures/` 아래에 저장되어 Git에 올라가지 않습니다.

## 기술 설계 상 주의

**고정 5초 품질 검증 장면**과 **실제 AI 경기 재생**은 별개의 콘텐츠입니다. 첫 번째는 애니메이션 검증용 연출이고, 두 번째는 AI가 실제로 벌인 경기의 기록입니다. 두 가지를 혼동하거나 시뮬레이션 결과를 미리 정한 것처럼 운영하지 않습니다.
