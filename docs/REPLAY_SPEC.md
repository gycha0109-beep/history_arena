# 경기 기록과 재생 설계 v0.1

## 왜 중요한가

AI 자동 대전에서 우연히 좋은 경기가 나왔을 때 **동일한 전투를 다시 재생하고 카메라만 바꾸어 녹화**할 수 있어야 한다.

## 현재 구현

- 고정 틱 카운터와 난수 시드 저장
- 경기 시작·임의 사건·종료 기록의 형식
- JSON으로 직렬화 가능한 Dictionary 생성

**중요:** 이것만으로는 정확한 리플레이가 불가능하다. 아직 캐릭터 상태나 AI 행동 기록이 없기 때문이다.

## 제안 기록 규격

```json
{
  "schema_version": 1,
  "simulation_hz": 60,
  "seed": 12345,
  "engine_version": "선정 버전",
  "fighter_a": "musashi",
  "fighter_b": "bruce_lee",
  "events": [
    {"tick": 0, "type": "match_started", "data": {"seed": 12345}}
  ]
}
```

위 예시는 **확장 목표**이며, 현재 코드가 엔진 버전이나 캐릭터 ID를 저장하지는 않는다.

### 두 가지 재생 전략

1. **시드 + 입력 재실행**: 작고 빠르지만 전투 로직, 물리, 애니메이션 업데이트가 바뀌면 결과가 달라질 위험이 있음.
2. **상태 기록 재생**: 캐릭터 위치·방향·행동 상태·피격 사건을 틱 단위로 기록하고 연출에서 재사용. 파일은 커지지만 영상 제작의 재현성에 유리함.

**잠정 추천:** 전투 시뮬레이션은 시드/행동 로그를, 영상 재생은 변환된 상태 기록을 우선 검증한다. 정확한 저장 빈도와 압축 방식은 프로토타입 결과로 결정한다.

### 반드시 확인할 테스트

- 같은 기록을 두 번 재생했을 때 이동·히트·KO 시점 일치
- 카메라를 바꾸어도 경기 결과 불변
- 게임 속도가 바뀌어도 논리 틱 순서 보존
- 버전이 달라 재생이 불가능한 기록은 명확한 오류로 처리
