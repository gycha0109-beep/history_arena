# 기술 설계 v0.1 — 레전더리 배틀

> 상태: 확정 원칙 + 제안된 세부 규격을 구분한 설계 초안. 실제 전투 AI·판정·리플레이는 아직 구현되지 않음.

## 1. 시스템 구성

```text
캐릭터/모션 데이터(Blender·Mixamo)
          ↓
Godot 에셋 임포트 → 캐릭터 표현 및 애니메이션
                            ↑
경기 설정 → 경기 진행(고정 틱) ← 자율 AI 행동 선택
                    ↓
             이동·판정·상태
                    ↓
            경기 이벤트·기록
                    ↓
       재생·카메라·이펙트 출력
                    ↓
          Movie Maker → FFmpeg
```

**분리 규칙**: 경기 판정은 AI·게임 규칙이 담당하고, 카메라·이펙트·녹화 시스템은 게임 결과를 바꾸지 않는다.

## 2. 기본 좌표와 시간

| 규칙 | 결정 |
|---|---|
| 가상 공간 | 3D 모델을 사용하는 2.5D 대전 |
| X축 | 캐릭터 간 수평 거리·이동 |
| Y축 | 높이 및 점프 |
| Z축 | 무대 깊이, 초기 전투는 지정 평면에 제약 |
| 게임 판정 | 고정 60Hz |
| 화면 | 기본은 측면 대전, 결정적 순간에만 시네마틱 |
| 화면 출력 | 평상시 게임 실행과 최종 영상 렌더링 분리 |

**검증 전 수치**: 무대 너비, 이동 속도, 공격 프레임, AI 판단 간격, 카메라 FOV, 최대 경기 길이. 이 값들은 시연을 통해 정한다.

## 3. 전투 및 캐릭터 구조(설계 목표)

- `MatchSession`: 경기 상태, 시드, 정수 틱, 사건 기록. **현재 기초 구현 있음.**
- `FighterState`: 위치·체력·전투 상태. **간이 구현 있음.**
- `MoveData`: 공격 준비/유효/회복 시간과 사거리·피해량. **임시 데이터 있음.**
- `HitResolver`: **1차원 사거리 기반의 간이 적중·피격 경직·KO 처리만 구현**. 실제 히트박스·가드 미구현.
- `AIController`: **간이 접근·후퇴·확률형 기술 선택 구현**. 정식 유틸리티 점수 AI는 추후 구현.
- `TempoDirector`: **6초간 적중 부재 시 접근/공격 확률만 조정하는 간이 처리 있음**. 별도 모듈화·반복 패턴 감지는 미구현.
- `Presentation`: 실제 상태에 맞춰 애니메이션, 카메라, 이펙트, 사운드 실행. **미구현.**
- `Replay`: 기록된 경기 재생 및 영상 출력. **미구현.**

### 최소 상태 흐름(제안)

`IDLE → APPROACH/RETREAT → STARTUP → ACTIVE → RECOVERY → IDLE`

피격·방어·회피·다운·KO는 상태별 선점 규칙을 추가하고, 공격 도중 상태 전환 가능 여부는 개별 기술 데이터로 관리한다.

### AI 설계 원칙

- 거리, 방향, 상대의 기술/상태, 자기 체력, 회복 시간 등을 평가해 행동 선택
- 캐릭터의 고유 특성에 맞게 가중치를 설정
- AI는 승패를 임의 조작하지 않음
- 템포 보조는 비정상적으로 긴 대치/반복만 개선; 확률 설정과 개입을 기록 가능하게 설계

## 4. 경기 기록

현재 구현된 `scripts/core/match_session.gd`는 **틱과 사건 기록의 최소 외피**다. 전투 재현성은 아직 보장하지 않는다.

- `schema_version`: 이벤트 형식의 호환성
- `simulation_hz`: 기록된 경기의 처리 주기
- `seed`: 난수 시작값
- `events`: 틱별 발생 사건
- 향후 `engine_version`, `assets_hash`, 입력/AI 결정 기록, 체크포인트 또는 상태 스냅샷 추가 필요
- 카메라 재편집을 위한 정확한 리플레이 설계는 [REPLAY_SPEC.md](REPLAY_SPEC.md) 참조

## 5. 영상 제작 구조

- 30~60초는 **최종 영상 길이**이며 실제 경기 길이와 동일하다고 가정하지 않는다.
- 선택한 경기의 사건/움직임을 기준으로 카메라를 제어해 세로형 9:16을 출력한다.
- 첫 단계는 5초 애니메이션 장면의 내보내기, 이후 경기 선택·자동 편집·FFmpeg 인코딩을 도입한다.
- 출력 목표 1080×1920 60FPS는 목표이지 GTX 1070에서 검증된 성능이 아니다.

## 6. 현재 상태 및 검증

이 단계의 실행 코드는 **Godot 구동, 60Hz 고정 틱, 가상 캐릭터 2명의 간이 자동 대전, 거리 기반 판정과 경기 기록**을 포함한다. 실제 3D 모델·애니메이션·히트박스·리플레이 플레이어·영상 렌더링은 포함되지 않는다.
